# 项目设计与验证

## 要解决的问题

AI 视频创作容易先堆画面，再补叙事理由。这个项目把“故事能否成立”与“镜头为什么存在”变成可检查的字段，让方法文档、示例和交互原型对应起来。

## 可以核验的内容

- `story-writing/`：人物、冲突、中心问题、节拍、场景与对白方法。
- `storyboard/`：主镜、景别、机位、构图、调度、视点与切镜检查。
- `prompts/` 与 `examples/`：输入格式和输出样例。
- `demo/app.js`：固定案例数据、选择/重排/删除/重置、参数调整、提示词复制、JSON 导出。
- Git 历史记录方法库到交互原型的演进，保留旧仓库的提交。

## 验证与限制

交互原型不评测创作质量，底部检查项需要人工判断。示例图是预制资产，不随参数变化而重绘。修改保存在内存，刷新后丢失；JSON 目前只支持导出。

公开成果包括可读方法、案例、源码和交互演示。目前不包含完整成片、自动化多模型调度或已完成的用户效果评测。

后续评测可以选定一组原创场景，记录未使用方法库和使用方法库后的分镜，由盲评者按空间连续性、信息变化、视点稳定性和切镜理由评分；目前未完成此实验。
